# [X01] 文件或选择变更后，只重做受影响的步骤

任务编号：X01-01。难度：进阶（先提交实施计划）。

开放计划：可申请认领；实际状态、负责人和认领结果以此Issue的标签及机器人回执为准。

## 你在帮谁解决什么问题

团队换了一个人员或模板，没必要把所有工作从头再做；但受影响的Word和审查也不能继续用旧结果。你要让程序知道各步骤依赖什么，保留历史，只重做受影响的步骤。

## 我们提供哪些材料

| 材料 | 在哪里 | 用来做什么 |
|---|---|---|
| 依赖图和历史文件 | [查看材料](../../samples/acceptance/shared/graph.json) | 依赖图列出步骤之间的读取关系；shared/history/提供本次教学用历史输出。 |
| 本任务测试入口 | [查看材料](../../samples/acceptance/X01/normal/input.json) | 人员替换、缺确认、依赖环、模板变化和报价变化；部分历史对象是合成扩展输入，不代表基座模块已实现。 |

以上专项原件已提供，取得和查看这些材料不需要真实客户资料或服务密钥。故意缺失/损坏的文件是异常测试，按用例报错或转核对，不向老师补要原件。测试包来自 [精确测试版本](https://github.com/iurp/fdex-tender-agent/blob/19433e19434354e113f6569b4a102684abac317c/samples/acceptance/README.md)；是否合入main以 [PR #23](https://github.com/iurp/fdex-tender-agent/pull/23) 为准。

## 你具体要做什么

已有基础与这次新增：基座支持指定一步重做并提示后续结果过期，还没有完整自动依赖图。本次扩展文件与JSON调度，不要求搭建Web服务或数据库。

1. 读取明确的依赖关系，找出本次变更直接影响哪一步，以及哪些后续步骤受影响。
2. 人员选用变化时重做匹配、Word、检查和归档；未受影响的文件保持原字节。
3. 模板变化与报价变化分别安排重跑，不把重跑全部作为唯一策略。
4. 每次写入新运行目录和新运行编号，旧文件与旧批准保留在旧目录，不能覆盖。
5. 变更需要重新确认但还没确认时，先停在相应步骤，不能直接装配或标完成。
6. 发现步骤相互循环依赖时给出明确错误；新结果不能继承旧版本已放行状态。

## 做完后交什么

- 依赖图配置、重跑计划、实际新旧运行目录和可读的执行记录。
- 实际重做/跳过步骤、文件内容指纹、旧历史保留以及失效确认/放行记录。

交付效果示例：

> 替换人员只重做M09、M13、M14、M18，M03、M04、M07、M08和M12保持不变。新的文档要重新检查，不能复制旧RELEASED状态充当新放行。

本次不要求或不能做的事：

- 不要求实现所有未完成业务模块，不拿合成历史文件冒充真实业务执行。
- 不改真实学员数据，不部署企业系统，也不自动批准新结果。

为模块协同提供可复现调度；业务确认仍由对应负责人处理。

## 怎么判断完成

先用本任务现成的用例验证，不能只演示一次正常结果：

| 用例 | 你要证明什么 |
|---|---|
| [正常](../../samples/acceptance/X01/normal/case.json) | 人员替换只重做受影响模块 |
| [待核对](../../samples/acceptance/X01/review/case.json) | 选择变更但未重新确认 |
| [异常](../../samples/acceptance/X01/abnormal/case.json) | 依赖环不能冒充全部完成 |
| [变更](../../samples/acceptance/X01/change/case.json) | 模板变化与报价变化分别最小重跑 |

交出这些用例的实际运行报告、原始输出和本次新增测试。

还要保留一次有关已生成文件的联调记录，说明你实际读了什么。如果先用独立教学输入验证新增部分，明确这个范围和接入方式，不能冒充整条流程已经接通。

只有材料完整不等于功能完成；固定公开样例通过也不能替代独立代码审查，复审还会改变合法输入检查是否硬编码。

## 技术附录

这里是实现时查阅的约定，不需要先背术语才能理解前面的任务。

| 术语 | 这道任务里的意思 |
|---|---|
| 依赖图 | 记录某一步需要先读取哪些步骤结果的关系表。 |
| 局部重跑 | 只重新执行本次变化影响的步骤。 |
| run_id | 一次执行的身份编号，用来区分新旧结果。 |

机器输出仍使用已有JSON约定，`bid-training.workflow.v1`只是程序统一读取结果的格式名称，不是额外业务目标。字段细节看 [接口说明](../../docs/interfaces.md)。

原需求验收索引：X01 公共最低标准。本次只检查上面写明的新增范围，不把整个模块的后续路线图都压进这一个任务。

自测先检查材料，再用你自己的模块运行结果接受检查：

```bash
python tools/task_acceptance.py verify-kit --module X01
python tools/task_acceptance.py run --module X01 --adapter adapters/x01.py --output outputs/x01-test-01
python -m unittest discover -s tests -v
```

第一条只检查材料完整性。第二条的适配器由你把自己的模块接进去，缺适配器不会算通过；每次用新输出目录。Windows命令、结果字段和PR证据见 [测试指南](../../docs/testing.md)，本任务操作卡见 [X01操作卡](../../samples/acceptance/X01/README.md)。维护PR合并后才在main启用相应专项CI，不提前宣称已启用。

只使用公开合成资料；确认人必须来自提供的记录，程序不能补造。工程合并不代表报价、真实签章、递交或业务验收已批准。
