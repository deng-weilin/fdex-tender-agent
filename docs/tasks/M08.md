# [M08] 从证书图片读取字段，看不清就标待核对

任务编号：M08-01。难度：进阶（先提交实施计划）。

开放计划：可申请认领；实际状态、负责人和认领结果以此Issue的标签及机器人回执为准。

## 你在帮谁解决什么问题

资料管理员收到几张证书图片，希望整理出人员编号、证号、资格和有效期。图片有时清楚，有时遮挡或损坏。你要真正读取图片，把看不清的字段留给人工核对，不能猜数字。

## 我们提供哪些材料

| 材料 | 在哪里 | 用来做什么 |
|---|---|---|
| 合成证书图片 | [查看材料](../../samples/acceptance/shared/ocr) | 4张清晰图片，以及有效期遮挡、过期、更新版、损坏图片；缺失原件是故意的异常。 |
| 本任务测试入口 | [查看材料](../../samples/acceptance/M08/normal/input.json) | 提供要读取的图片及有效期判断日期；human-correction用例另给具名模拟核对记录。 |

以上专项原件已提供，取得和查看这些材料不需要真实客户资料或服务密钥。故意缺失/损坏的文件是异常测试，按用例报错或转核对，不向老师补要原件。测试包来自 [精确测试版本](https://github.com/iurp/fdex-tender-agent/blob/19433e19434354e113f6569b4a102684abac317c/samples/acceptance/README.md)；是否合入main以 [PR #23](https://github.com/iurp/fdex-tender-agent/pull/23) 为准。

图片识别方式由实施计划说明。可以选择本地识别；如果选择外部模型服务，接入条件要另行说明，不上传密钥，也不能把没有执行的识别写成已通过。

## 你具体要做什么

已有基础与这次新增：基座目前读的是随图片提供的文字说明，并检查图片是否存在；这不是图片识别。本次新增从图片本身读取可见字段。

1. 打开4张清晰图片，提取人员编号、证书编号、资格名称和有效期。
2. 每个字段说明来自哪张图片哪个可见区域；不从文件名或已有文字说明猜答案。
3. 日期被遮挡时写未知并提示待核对，不能补出完整日期，也不能自动判有效。
4. 发现损坏图片或只有登记记录却没有原件时，说明对应问题。
5. 同一人的新旧证书分别保留身份和版次，不用新图覆盖旧原件，不自动选用新证。
6. 有人提供字段核对记录时，保存第二来源、核对人、时间和核对对象；明确该值不是从遮挡图片读到的。

## 做完后交什么

- material_index.json、字段及图片位置证据、中文材料问题清单。
- 说明实际使用的识别方法；没有运行识别就不能写识别已通过。

交付效果示例：

> 图片能读到证号OCR-DEMO-003，但有效期被遮挡：证号登记，日期为未知，状态为待核对。后来收到具名核对记录，另存核对值和来源，不伪装成图片可见事实。

本次不要求或不能做的事：

- 读到证书内容不等于证明证书真实有效。
- 不使用真实人员证书；不做真实任命或投标授权。
- 不要求开发资料管理网页。

M09用材料索引核对候选；项目实际选用仍需独立确认。

先用本任务现成的用例验证，不能只演示一次正常结果：

交出这些用例的实际运行报告、原始输出和本次新增测试。

本任务直接从实际文件、图片或给定数值开始，用它们运行即可，不要求先等其他模块生成结果。与后续程序交接时，说明输出怎样被读取。

字段证据要回到实际图片区域，注明识别方法和执行记录。

只有材料完整不等于功能完成；固定公开样例通过也不能替代独立代码审查，复审还会改变合法输入检查是否硬编码。
