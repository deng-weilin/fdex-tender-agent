# [M14] 检查实际 Word，找出表格和附件的错位

任务编号：M14-01。难度：常规。

开放计划：可申请认领；实际状态、负责人和认领结果以此Issue的标签及机器人回执为准。

## 你在帮谁解决什么问题

文档生成程序报告“成功”，但人员可能填错列，证书也可能放在错误人员下面。审核人需要看到具体问题在哪，不能只信生成日志。你要打开实际Word，对照原资料检查位置和对应关系。

## 我们提供哪些材料

| 材料 | 在哪里 | 用来做什么 |
|---|---|---|
| 实际Word与对应记录 | [查看材料](../../samples/acceptance/shared/word) | 提供正常文档、正确/错位trace记录，以及图片互换、漏图、错项目、旧人员和残留占位符文档。 |
| 本任务测试入口 | [查看材料](../../samples/acceptance/M14/normal/input.json) | 给出需要审查的文件、确认资料、检查范围和旧版放行记录。 |

以上专项原件已提供，取得和查看这些材料不需要真实客户资料或服务密钥。故意缺失/损坏的文件是异常测试，按用例报错或转核对，不向老师补要原件。测试包来自 [精确测试版本](https://github.com/iurp/fdex-tender-agent/blob/19433e19434354e113f6569b4a102684abac317c/samples/acceptance/README.md)；是否合入main以 [PR #23](https://github.com/iurp/fdex-tender-agent/pull/23) 为准。

## 你具体要做什么

已有基础与这次新增：基座能检查一些漏图、错项目和旧资料问题。本次新增实际表格单元格与可见图片关系的定位检查。

1. 打开实际Word，对照确认人员核对表格的具体表、行、列。
2. 核对每个人下面实际显示的证书图片，不只检查压缩包里有没有这些图片。
3. 检查填写对应记录是否真的指向正确单元格和图片；记录缺失或指错位置就报告问题。
4. 找出错项目、旧人员、未处理占位符、缺图和互换附件，并给出具体位置。
5. 分别说明已检查的人员章节范围和未检查的全本范围，不能写全本100%通过。
6. 文件改动后旧放行失效；问题修好后要重新检查，不能只把状态手动改成通过。

## 做完后交什么

- review_result.json 和让制作人员能直接修改的问题清单。
- 每个问题的具体位置、依据、严重程度、接手角色和复测结果；没有视觉检查就明确没有做。

交付效果示例：

> 人员甲的证号写在第1张表第2行第3列；证书附件却显示人员乙的图片，应定位到该图片关系。即使3张图片都在文件里，顺序配错也不能通过。

本次不要求或不能做的事：

- 本任务检查已有Word，不要求你重新生成一份合格标书。
- 不自动作出真人放行，不把局部检查当整本或真实递交批准。

把问题交给制作人员修正；指定版本的放行由具名审核人另行作出。

## 怎么判断完成

先用本任务现成的用例验证，不能只演示一次正常结果：

| 用例 | 你要证明什么 |
|---|---|
| [正常](../../samples/acceptance/M14/normal/case.json) | 表格单元格与实际图片关系都正确 |
| [待核对](../../samples/acceptance/M14/review/case.json) | 没有填写对应记录不能声称位置都已检查 |
| [异常](../../samples/acceptance/M14/abnormal/case.json) | 填写对应记录指错单元格但Word本身正常 |
| [变更](../../samples/acceptance/M14/change/case.json) | 图片都在，但甲乙两人的证书互换，仍要检出并定位 |
| [缺图片](../../samples/acceptance/M14/missing-image/case.json) | 实际Word缺少一张可见证书图片 |
| [项目不符](../../samples/acceptance/M14/wrong-project/case.json) | 实际Word写成另一个项目名称 |
| [旧人员残留](../../samples/acceptance/M14/old-person/case.json) | 实际Word残留未选用的旧人员姓名 |
| [占位符残留](../../samples/acceptance/M14/placeholder/case.json) | 实际Word还有没有填写的占位符 |

交出这些用例的实际运行报告、原始输出和本次新增测试。

还要保留一次有关已生成文件的联调记录，说明你实际读了什么。如果先用独立教学输入验证新增部分，明确这个范围和接入方式，不能冒充整条流程已经接通。

报告必须依据实际提供的DOCX，附表/行/列、段落或图片关系的具体位置；不能只引用生成日志。

只有材料完整不等于功能完成；固定公开样例通过也不能替代独立代码审查，复审还会改变合法输入检查是否硬编码。

## 技术附录

这里是实现时查阅的约定，不需要先背术语才能理解前面的任务。

| 术语 | 这道任务里的意思 |
|---|---|
| trace | 填写对应记录，说明某份资料被放到文档的哪个位置。 |
| 图片关系 | Word正文中某个可见图片位置实际引用哪份图片。 |
| BLOCKER | 相关范围不能继续使用的阻断问题。 |

机器输出仍使用已有JSON约定，`bid-training.workflow.v1`只是程序统一读取结果的格式名称，不是额外业务目标。字段细节看 [接口说明](../../docs/interfaces.md)。

只使用公开合成资料；确认人必须来自提供的记录，程序不能补造。工程合并不代表报价、真实签章、递交或业务验收已批准。
