# [M06] 发现招标修改后，列出需要重做的内容

任务编号：M06-01。难度：进阶（先提交实施计划）。

开放计划：可申请认领；实际状态、负责人和认领结果以此Issue的标签及机器人回执为准。

## 你在帮谁解决什么问题

标书已经准备了一部分，采购方又发来修改通知。负责人需要知道哪里改了、哪些工作要重做、原来的确认还能不能用。你要做一份可追溯的修改影响清单。

## 我们提供哪些材料

| 材料 | 在哪里 | 用来做什么 |
|---|---|---|
| 原始招标节选 | [查看材料](../../samples/e2e/core-normal/tender/tender.md) | 包含原人数、证书日期基准和投标截止。 |
| 明确修改通知 | [查看材料](../../samples/modules/M06/normal/amendment.md) | 人数3→4，证书有效期判断基准11月1日→11月8日，投标截止也后移。 |
| 本任务测试入口 | [查看材料](../../samples/acceptance/M06/normal/input.json) | 还提供覆盖关系不明、其他项目通知和只改标题的情况。 |

以上专项原件已提供，取得和查看这些材料不需要真实客户资料或服务密钥。故意缺失/损坏的文件是异常测试，按用例报错或转核对，不向老师补要原件。测试包来自 [精确测试版本](https://github.com/iurp/fdex-tender-agent/blob/19433e19434354e113f6569b4a102684abac317c/samples/acceptance/README.md)；是否合入main以 [PR #23](https://github.com/iurp/fdex-tender-agent/pull/23) 为准。

## 你具体要做什么

已有基础与这次新增：基座能发现输入变化并拒绝部分旧确认，但还不会清楚列出变更及受影响工作。本任务补这个清单，不无差别重跑全部模块。

1. 对照旧原文与修改通知，逐项列出旧值、新值和出处。
2. 指出相关要求、资料、制作任务、文档和确认中哪些需要更新。
3. 人数、有效期基准等实质变化后，标记受影响的旧确认和旧放行已失效；不能继续拿旧文件去模拟提交。
4. 没改的要求、章节和历史输出保留，不全部重做。
5. 通知没有说明替代关系时请负责人确认；其他项目的通知不能覆盖本项目。
6. 只改标题错别字时，与人数或截止变化区别处理。

## 做完后交什么

- change_impact.json 和中文修改/重做清单。
- 旧新出处、受影响对象、需要重新确认的事项，以及保留的未受影响内容。

交付效果示例：

> 人员3名改成4名，需要重新核对候选、分工、人员表和确认；投标截止后移，需要更新有关任务期限。技术方案原文没有变化，不把它写成必须全部重做。

本次不要求或不能做的事：

- 不自行对采购方发送澄清问题，不自行认定通知效力。
- 不自动补人员或业务批准，也不删除旧版本。

把影响清单交给相关模块及负责人；X01可用它安排局部重跑。

## 怎么判断完成

先用本任务现成的用例验证，不能只演示一次正常结果：

| 用例 | 你要证明什么 |
|---|---|
| [正常](../../samples/acceptance/M06/normal/case.json) | 补遗调整人数、资格基准与截止 |
| [待核对](../../samples/acceptance/M06/review/case.json) | 无覆盖关系不裁定补遗 |
| [异常](../../samples/acceptance/M06/abnormal/case.json) | 其他项目补遗拒绝覆盖 |
| [变更](../../samples/acceptance/M06/change/case.json) | 标题勘误不把无关模块全部重做 |

交出这些用例的实际运行报告、原始输出和本次新增测试。

还要保留一次有关已生成文件的联调记录，说明你实际读了什么。如果先用独立教学输入验证新增部分，明确这个范围和接入方式，不能冒充整条流程已经接通。

只有材料完整不等于功能完成；固定公开样例通过也不能替代独立代码审查，复审还会改变合法输入检查是否硬编码。
