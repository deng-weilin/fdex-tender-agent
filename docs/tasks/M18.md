# [M18] 整理可复用的模板和方法，保留批准记录

任务编号：M18-01。难度：入门。

开放计划：可申请认领；实际状态、负责人和认领结果以此Issue的标签及机器人回执为准。

## 你在帮谁解决什么问题

投标做完后，资料管理员想把好用的模板、规则和脱敏章节留给下一个项目。但项目资料不能直接乱复用，更不能把旧项目批准当成新项目批准。你要整理可复用候选和各自的使用边界。

## 我们提供哪些材料

| 材料 | 在哪里 | 用来做什么 |
|---|---|---|
| 合成复用材料 | [查看材料](../../samples/acceptance/shared/reuse) | 通用规则、脱敏章节、修改版，以及一份虽是合成但明确禁止公开的模拟材料。 |
| 本任务测试入口 | [查看材料](../../samples/acceptance/M18/normal/input.json) | 同时引用Word模板；包含未批准、禁止公开、内容改变和具名批准用例。 |

以上专项原件已提供，取得和查看这些材料不需要真实客户资料或服务密钥。故意缺失/损坏的文件是异常测试，按用例报错或转核对，不向老师补要原件。测试包来自 [精确测试版本](https://github.com/iurp/fdex-tender-agent/blob/19433e19434354e113f6569b4a102684abac317c/samples/acceptance/README.md)；是否合入main以 [PR #23](https://github.com/iurp/fdex-tender-agent/pull/23) 为准。

## 你具体要做什么

已有基础与这次新增：基座已经能归档原件与输出。本次在归档基础上增加三类复用候选和批准记录，不重做完整归档平台。

1. 整理至少1个模板适配、1条规则、1份脱敏章节，逐个说明来源、适用范围和版本。
2. 先登记为候选，没有具名批准不能自动用于下次已确认响应。
3. 保存批准对象的内容指纹、批准人、时间和范围；内容变化后旧批准失效。
4. 公开导出前核对每份文件是否明确允许公开；任一材料禁止公开就不能产出本次公开包。
5. 不要把价格、人员、客户信息或旧批准偷偷带进通用章节。
6. 保留旧版本和本次记录，能追溯复用资产从哪次运行来。

## 做完后交什么

- reuse_candidates.json、中文候选/批准清单和符合许可范围的候选导出包。
- 归档关联与新旧版本记录；不能导出时交明确的问题结果，不交违规ZIP。

交付效果示例：

> 模板、规则和脱敏章节都可以列为候选；未批准时仍不能成为下次已确认内容。规则改了一句，针对旧字节的批准失效。明确可公开的教学候选允许按测试要求导出，不等于业务已批准复用。

本次不要求或不能做的事：

- 不自动批准素材，不继承上一个项目的人员、价格或业务确认。
- 本次候选包不替代基座的完整运行归档，不需要建设企业知识库网页。

由有权负责人批准复用范围；下一项目仍独立核对和确认具体响应。

## 怎么判断完成

先用本任务现成的用例验证，不能只演示一次正常结果：

| 用例 | 你要证明什么 |
|---|---|
| [正常](../../samples/acceptance/M18/normal/case.json) | 三类可复用候选仍待批准 |
| [待核对](../../samples/acceptance/M18/review/case.json) | 未批准候选不能成为下次确认响应 |
| [异常](../../samples/acceptance/M18/abnormal/case.json) | 缺公开许可即不创建公开包 |
| [变更](../../samples/acceptance/M18/change/case.json) | 复用内容改变后旧批准失效 |
| [有批准记录](../../samples/acceptance/M18/approved/case.json) | 具名批准允许复用但不继承业务确认 |

交出这些用例的实际运行报告、原始输出和本次新增测试。

还要保留一次有关已生成文件的联调记录，说明你实际读了什么。如果先用独立教学输入验证新增部分，明确这个范围和接入方式，不能冒充整条流程已经接通。

只有材料完整不等于功能完成；固定公开样例通过也不能替代独立代码审查，复审还会改变合法输入检查是否硬编码。

## 技术附录

这里是实现时查阅的约定，不需要先背术语才能理解前面的任务。

| 术语 | 这道任务里的意思 |
|---|---|
| 脱敏 | 去掉不应复用的项目、人员和客户等信息，只保留通用结构。 |
| 复用候选 | 可能用于后续项目的材料，尚未自动取得使用批准。 |

机器输出仍使用已有JSON约定，`bid-training.workflow.v1`只是程序统一读取结果的格式名称，不是额外业务目标。字段细节看 [接口说明](../../docs/interfaces.md)。

原需求验收索引：M18-AC1..AC4。本次只检查上面写明的新增范围，不把整个模块的后续路线图都压进这一个任务。

自测先检查材料，再用你自己的模块运行结果接受检查：

```bash
python tools/task_acceptance.py verify-kit --module M18
python tools/task_acceptance.py run --module M18 --adapter adapters/m18.py --output outputs/m18-test-01
python -m unittest discover -s tests -v
```

第一条只检查材料完整性。第二条的适配器由你把自己的模块接进去，缺适配器不会算通过；每次用新输出目录。Windows命令、结果字段和PR证据见 [测试指南](../../docs/testing.md)，本任务操作卡见 [M18操作卡](../../samples/acceptance/M18/README.md)。维护PR合并后才在main启用相应专项CI，不提前宣称已启用。

只使用公开合成资料；确认人必须来自提供的记录，程序不能补造。工程合并不代表报价、真实签章、递交或业务验收已批准。
