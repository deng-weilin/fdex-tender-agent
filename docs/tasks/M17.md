# [M17] 把中标项目的投标承诺交给交付团队

任务编号：M17-01。难度：常规。

开放计划：暂未开放，不要认领。维护者补齐练习原件和测试后才开放，不要求学员先自备这些材料。

## 你在帮谁解决什么问题

项目中标后，交付团队需要知道投标时承诺了哪些人员、工期、成果和价格。后来草稿又改过，不能拿错版本。你要从实际提交版本整理承诺，并与提供的模拟合同核对差异。

## 我们提供哪些材料

| 材料 | 在哪里 | 用来做什么 |
|---|---|---|
| 规划说明 | [查看材料](../../samples/modules/M17/normal/input.json) | 完整中标与合同练习原件尚未准备。 |
| 开放前需补齐 | 尚未准备，不是现成练习包 | 确认中标记录、实际提交的模拟文件与报价、一份植入2处差异的模拟合同，以及缺合同/未中标样本。 |

现有说明或部分样例不等于完整测试材料已配齐；示意例子也不是现成原件。不要把基座的未确认/过期样例当成这个新模块的专项测试。

## 你具体要做什么

已有基础与这次新增：基座没有中标后交接模块。本任务规划一份提交版本与模拟合同的核对，不替代合同或项目系统。

1. 确认有中标依据，并锁定实际提交版本，不从后来的新草稿提取承诺。
2. 列出范围、人员、工期、交付物、价格和付款等输入中实际存在的承诺，标出文件位置。
3. 逐项与给定合同草案核对，找出2处预设差异及双方出处。
4. 没有合同就列待取得，不能写已经完成合同一致性检查。
5. 未中标或没有接收人确认时，不标成已完成中标交接。
6. 列出负责人和接收状态，保留原提交版本以及待核对事项。

## 做完后交什么

- handover_package.json、承诺台账和差异清单。
- 原提交版本、合同对应位置、接收记录与未完成交接事项。

本次不要求或不能做的事：

- 不起草最终合同条款，不真实签约或启动客户项目。
- 中标、签约、项目启动和交接完成是不同状态。

由合同与项目负责人确认接收，交给后续交付流程。
