# [M04] 从招标原文整理要求，并标出出处

任务编号：M04-01。难度：常规。

开放计划：可申请认领；实际状态、负责人和认领结果以此Issue的标签及机器人回执为准。

## 你在帮谁解决什么问题

售前同事拿到招标文件，需要知道必须准备什么、截止在哪一天、表格有什么要求。只给他一段概括很难核对。你要从原文整理出逐条要求，并让每一条都能回到原文位置。

## 我们提供哪些材料

| 材料 | 在哪里 | 用来做什么 |
|---|---|---|
| 无标签原文及变化样本 | [查看材料](../../samples/acceptance/shared/tender) | plain.md有12条要求；conflict.md增加冲突人数；plain-v1.1.md修改一条；另有正文不可读样本。 |
| 本任务测试入口 | [查看材料](../../samples/acceptance/M04/normal/input.json) | 说明读取哪份原文、来源编号和仅阅读节选的范围。 |

以上专项原件已提供，取得和查看这些材料不需要真实客户资料或服务密钥。故意缺失/损坏的文件是异常测试，按用例报错或转核对，不向老师补要原件。测试包来自 [精确测试版本](https://github.com/iurp/fdex-tender-agent/blob/19433e19434354e113f6569b4a102684abac317c/samples/acceptance/README.md)；是否合入main以 [PR #23](https://github.com/iurp/fdex-tender-agent/pull/23) 为准。

## 你具体要做什么

已有基础与这次新增：基座只会读取带[R-01]等人工标签的Markdown。本次要让它读没有这些标签的自然文本；不要求支持任意PDF或扫描件。

1. 读取实际原文，不把老师的预期结果当输入。
2. 整理12条要求：要求的内容、类别、涉及什么材料或期限，以及原文文件和行号。
3. 没有公布评分分值时保持未知，不能补造分数；“必须做”也不能一律解释成“不做就废标”。
4. 遇到两条相互冲突的要求，保留双方原文，标需要负责人解释，不擅自选一条。
5. 只读节选就说明只覆盖节选，不能声称审完全部招标文件。
6. 同一条要求重复运行保持身份编号稳定；一条内容修改后保留旧新对应关系，其他要求不乱换编号。

## 做完后交什么

- tender_brief.json 和中文要求摘要。
- 每条要求的原文、出处和需要解释的冲突清单。

交付效果示例：

> 要求：人员至少3名。出处：plain.md第4行。另一份补充要求写“恰为2名”且没说明替代关系时，两条都保留，并提示人数要求冲突，等待负责人确认。

本次不要求或不能做的事：

- 不负责判断公司真的满足要求，不负责生成标书。
- 本次不要求通用OCR，也不要求自建题库或接真实采购平台。

M07把这些要求变成制作任务；M09根据要求检查资料候选。

## 怎么判断完成

先用本任务现成的用例验证，不能只演示一次正常结果：

| 用例 | 你要证明什么 |
|---|---|
| [正常](../../samples/acceptance/M04/normal/case.json) | 无R标签原文中的12条要求 |
| [待核对](../../samples/acceptance/M04/review/case.json) | 人数冲突保留双方原文 |
| [异常](../../samples/acceptance/M04/abnormal/case.json) | 不可读正文不能生成12条伪要求 |
| [变更](../../samples/acceptance/M04/change/case.json) | 一条改变后保留语义实体与版本映射 |

交出这些用例的实际运行报告、原始输出和本次新增测试。

还要保留一次有关已生成文件的联调记录，说明你实际读了什么。如果先用独立教学输入验证新增部分，明确这个范围和接入方式，不能冒充整条流程已经接通。

只有材料完整不等于功能完成；固定公开样例通过也不能替代独立代码审查，复审还会改变合法输入检查是否硬编码。
